01 / 问题

学习工具不缺功能，缺的是一条闭环。

教材、笔记、检索和复习常常分散在四个工具里。每多一次复制粘贴，记忆就多断一次。

01

教材进不来

PDF、网页、课程笔记格式各异，清洗和整理占掉了真正学习的时间。

02

复习靠意志

没有调度，记过的内容不会在恰当的时间回来；想复习时也不知道该复习什么。

03

找到了，却不知道出处

搜索给出一段答案，却说不清来自哪本教材、哪一次修订。

这个项目把教材段落、笔记、检索文档和复习状态放进同一个 seekdb，用一次发布事务串起来。

02 / 闭环

从一份 Markdown，到下一次到期。

六个步骤都在同一个工作台里完成，中间没有导出、导入和手工同步。

  1. 01

    导入

    粘贴 Markdown，解析成安全 AST 与可校订的草稿。

  2. 02

    校订

    检查段落、笔记字段与 warning，确认后才进入发布。

  3. 03

    发布

    教材、笔记、卡片与 SearchDocument 在同一事务写入。

  4. 04

    检索

    按日语 ngram、英语 space 配置查原文、读音与释义。

  5. 05

    复习

    FSRS 按真实评分计算 stability、difficulty 与 dueAt。

  6. 06

    统计

    保持率、连续天数与 14 天节奏直接从数据库聚合。

没有确认发布，就不会生成卡片或检索文档。没有复习记录，统计页就保持空白。

03 / 能力

为“真实可用”做的取舍。

不是功能清单的堆叠，而是让每一步都能被验证。

IMPORT

教材导入与人工校订

Markdown 解析为安全 AST；草稿预览展示段落、笔记与 warning。发布是显式动作，预览不会冒充结果。

SEEKDB

全文检索，带出处

业务文本与 SearchDocument 同事务发布；MATCH ... AGAINST 参数化查询。日语走 ngram，英语走 space，由语言插件配置决定。

FSRS

到期才出现

ts-fsrs 4.7 计算调度；评分写入只追加的 review_logs。到期队列只包含真正到期的卡片，未来任务不提前计入。

PROGRESS

真实进度

累计复习、今日复习、保持率、连续天数与 14 天节奏全部来自 cards、card_scheduling_states 与 review_logs。

PLUGIN

语言插件化

英语与日语各自注册 NoteType、规范化函数和检索配置。核心路由没有按语言写死分支，新增语言不改通用流程。

WEB

Web 微内核

AppShell 独占布局，插件只向 route、sidebar、headerAction 三类贡献点注册。五个通用页面也由内置插件装配。

05 / 技术结合

seekdb 不是一个连接串，而是流程的一部分。

首版只使用 seekdb 一个数据库。业务表、全文检索文档和复习状态共享同一套事务与时间基准。

WEB React + Vite AppShell / WebPluginRegistry
→
API Hono /v1 计划 / 导入 / 检索 / 复习
→
DOMAIN 领域服务 事务编排与 NoteType 校验
→
STORAGE mysql2 参数化 SQL 仓储 / 检索 / 调度状态
→
DATABASE seekdb 唯一数据库
插件组合入口 language-en language-ja importer-markdown scheduler-fsrs → DefaultPluginRegistry

  • 同事务发布

    教材段落、笔记、卡片与 SearchDocument 一起提交；任何一步失败全部回滚，不会出现“文本写入了但检索不到”的半成品。

  • 检索策略由语言包决定

    日语 normalized_text 走 ngram，英语 original_text 走 space。列选择来自 searchConfig，不在 SQL 里按语言代码写分支。

  • 时间基准统一

    连接池统一使用 UTC，到期判断改用 UTC_TIMESTAMP(3)，修复了数据库 +08:00 与 Node 进程时区漂移导致的口径差。

  • 单库边界

    不引入 PostgreSQL 或独立 MySQL。11 张表承载计划、教材、笔记、卡片、调度状态与只追加的 ReviewLog。

06 / 运行

十分钟内，从零到第一次复习。

需要 Node.js 22+、pnpm 10 与 Docker（或 OrbStack）。seekdb 以容器方式启动。

  1. 01

    启动 seekdb

    首次拉取镜像与健康检查可能需要几分钟。

  2. 02

    安装依赖并迁移

    复制环境变量模板，按本地密码修改占位值。

  3. 03

    分别启动 API 与 Web

    API 监听 8787，Web 监听 5173；Vite 将 /v1 代理到 API。

数据库连接、迁移与真实 seekdb 验证细节见仓库中的 docs/sprint1/mvp-plan.md。

终端 
# 1. 启动 seekdb
docker compose -f infra/seekdb/docker-compose.yml up -d

# 2. 安装依赖并迁移
cp .env.example .env
pnpm install
pnpm migrate

# 3. 两个终端分别启动
pnpm dev:api   # http://localhost:8787
pnpm dev:web   # http://localhost:5173
验证样例 / lesson.md

按步骤验收

  1. 打开 http://localhost:5173，新建「日语 N4 核心词汇」。语言选项来自 GET /v1/languages。
  2. 在教材工坊粘贴左侧 Markdown，解析草稿后确认发布。
  3. 预期：教材工坊出现 2 段、2 条笔记、2 张卡片。
  4. 混合检索输入「海」，应命中笔记与教材段落，并显示来源修订与相关度。
  5. 在记忆复习中完成 2 轮评分，统计页出现真实复习数字。
